# Контракт модулів

Не створюємо порожні редактори. Реєстр у `core/module-registry/index.js` описує всі заплановані модулі.

Майбутній модуль має власну папку та `entry`, що динамічно імпортує редактор. Експортований `mount(container, services)` повертає `dispose()`. У services передаються спільний файловий API й обробник повідомлень. dispose прибирає слухачі, таймери та Workers.

Реєстр розрізняє `plannedFormats` (плани) і `supportedFormats` (реалізовані формати), а також містить `dependencies` та `offlineResources`. Порожній `entry` не дає права показувати кнопку запуску. Зміна статусу допускається після реалізації конкретного корисного набору функцій. Частковий редактор має явно описувати свої обмеження.

У спільному сховищі запис: id, name, blob, moduleId, schemaVersion, createdAt, updatedAt, size, type. Для редагованих проєктів зберігайте внутрішню модель у Blob із версією схеми; стандартний експорт реалізуйте окремо. Запис вважається успішним лише після завершення транзакції IndexedDB.

Архіватор реалізовано в `archiver/`. Його `mount` повертає об’єкт із `canLeave()` і `dispose()`. Маршрутизатор очікує завершення збереження перед виходом. `services.fileId` відкриває запис зі спільного сховища. Файловий API, резервні копії й автозбереження реалізовані; об’єднання конфліктів вкладок поки немає. Service Worker та селективне кешування додаються окремим етапом.
